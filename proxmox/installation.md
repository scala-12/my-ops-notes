# Proxmox VE installation

Инструкция для домашнего сервера.

## Install

С большинством полей проблем не возникает. Единственное, что стоит поменять - разделы диска:
- maxroot: 32 GB (должно быть достаточно для системы),
- minfree: 16 GB (резервное свободное место),
- swapsize: 4-8 GB (больше ОЗУ - меньше SWAP).

Еще стоит сразу указать статичный ip-адрес.

## Check network

1. Откройте веб-интерфейс по адресу `https://<IP-адрес-сервера>:8006` и войдите под `root`, используя пароль, заданный при установке
1. Закрепите за сервером постоянный IP-адрес
1. Убедитесь, что шлюз и DNS-сервер указаны верно. Не меняйте сетевые настройки удалённо, если не знаете, как восстановить доступ к серверу локально

## Repositories settings (No-subscribtion) and System update

1. Если у вас нет подписки Proxmox, откройте **Node → Updates → Repositories**:
    - Отключить репозитории `enterprise.proxmox.com/...`
    - Добавить вместо отключенных репозиториев **No-subscribtion**-варианты для нужной версии Proxmox VE
    - [Опционально] Отключить проверку подписки как уведомление при входе:
        1. Открыть **/usr/share/javascript/proxmox-widget-toolkit/proxmoxlib.js**
        1. Найти блок кода с проверкой подписки или строчку с `No valid subscription`
        1. Закомментировать строку с показом модалки `No valid subscription`
1. Нажмите **Refresh**, затем установите доступные обновления через **Node → Updates → Upgrade**.
1. Перезагрузите узел, если обновлялись ядро или системные компоненты, и проверьте, что веб-интерфейс и виртуальные машины снова доступны.

## Storage and Time

1. В **Datacenter → Storage** проверьте доступные хранилища и их назначение. Обычно ISO-образы и шаблоны хранятся в `local`, а диски VM - в `local-lvm` или выбранном вами хранилище.
    - На SSD стоит оставить *Disk image*, *Container*, *Snippets* (его особо без разницы где),
    - На HDD хранить *ISO image*, *Container template*, *Backup*, *Import*.
1. Перед созданием VM проверьте свободное место и тип файловой системы. Не меняйте настройки существующего хранилища, не проверив, где находятся диски VM и резервные копии.
1. Проверьте часовой пояс и синхронизацию времени в **Node → System → Time**. Корректное время важно для журналов, сертификатов и резервного копирования.

## User account

Для повседневной работы можно создать отдельную учётную запись Proxmox в **Datacenter → Permissions → Users** и назначить ей только необходимые права. Сначала проверьте вход под этой учётной записью в отдельном окне браузера. Не отключайте и не ограничивайте `root` до проверки нового доступа; для административных задач может понадобиться полный доступ к узлу и хранилищам.
- К примеру, можно создать Permissions для Path `/` Role `PVEAuditor` и Path `/vms` Role `PVEAdmin`.

Используйте уникальный длинный пароль. Не используйте одну учётную запись для всех домашних пользователей.

## Backup

1. Подключите отдельное хранилище для резервных копий: например, NAS или диск, который не является единственным диском с данными VM.
1. В **Datacenter → Backup** создайте задание резервного копирования, выберите нужные VM/контейнеры, расписание и политику хранения копий.
    - Во вкладке **Retention** укажите, сколько копий хранить. К примеру, схема *Дед-Отец-Сын*:
        - *Keep Last* / *Hourly* / *Daily*: `0`
        - *Keep Weekly*: `4` (хранить последние 4 недели по отдельности)
        - *Keep Monthly*: `12` (хранить по одному бэкапу на конец каждого месяца за последний год)
        - *Keep Yearly*: `1` (хранить один архивный годовой бэкап)
    - Для *Note Template* можно использовать шаблон:
        ```
        Cluster: {{cluster}} | Node: {{node}} | VM: {{vmid}} ({{guestname}})
        ```
1. Выполните первую копию вручную и проверьте результат в **Task History**.
1. Периодически проверяйте восстановление хотя бы одной VM. Снимки (**snapshots**) удобны перед изменениями, но не заменяют резервные копии.

Если пока нет отдельного хранилища, настройте копирование туда, где есть свободное место, понимая, что отказ диска сервера может уничтожить и VM, и копии.

## Restricting network access

### Firewall

Настройка встроенного фаервола в Proxmox VE построена по иерархическому принципу и включает три уровня: Datacenter (Кластер) → Node (Хост) → VM/Container (Виртуальная машина/Контейнер). Главное правило при работе с ним: сначала создайте разрешающие правила для управления, и только потом активируйте фаервол, иначе вы заблокируете себе доступ к веб-панели.

1. Перейдите в **Datacenter -> Firewall -> IP Sets**, создайте группу (например, с именем management)
1. Внутри этой группы добавьте IP-адрес вашего рабочего компьютера или подсеть вашей административной сети (например, 192.168.1.0/24)
1. Перейдите в **Datacenter -> Firewall**
1. Добавьте разрешающее правило:
	- *Direction*: `IN`
	- *Action*: `ACCEPT`
	- *Macro*: `WebManagement` (автоматически откроет порты 8006 и 5900-5999 для консоли)
	- *Source*: `+management`
1. Перейдите в **Datacenter -> Firewall -> Options**, установите параметр *Firewall* в значение `Yes`.
1. **На уровне Виртуальной машины**: Включение для ВМ состоит из двух этапов:
	- Перейдите в **VM -> Firewall -> Options** и включите параметр Firewall.
	- Перейдите в **VM -> Hardware**, выберите сетевой интерфейс (net0), нажмите *Edit* и обязательно поставьте галочку *Firewall*. Без этого правила для конкретной ВМ работать не будут!

### Brute-force protection

1. Установите *Fail2ban* на хост PVE
    ```bash
    apt update && apt install fail2ban -y
    ```
1. Добавить файл **/etc/fail2ban/jail.local**
    ```ini
    [DEFAULT]
    # Игнорировать локальные адреса, чтобы случайно не заблокировать себя
    ignoreip = 127.0.0.1/8 ::1 192.168.1.0/24

    # Время блокировки (10 минут)
    bantime  = 10m

    # Окно времени, за которое считаются ошибки (10 минут)
    findtime = 10m

    # Количество разрешенных неудачных попыток перед баном
    maxretry = 3

    # Использовать систему nftables/iptables для блокировки
    banaction = nftables-multiport

    # --- ЗАЩИТА SSH ---
    [sshd]
    enabled = true
    port    = ssh
    logpath = %(sshd_log)s
    backend = %(sshd_backend)s

    # --- ЗАЩИТА ВЕБ-ПАНЕЛИ PROXMOX ---
    [proxmox]
    enabled = true
    port    = 8006
    filter  = proxmox
    logpath = /var/log/daemon.log
    backend = systemd
    maxretry = 3

    # --- Защита от повторяющихся атак ---
    # нужно убедиться, что роутер правильно передает реальные IP-адреса клиентов (пробрасывает заголовки),
    # иначе Fail2ban может ошибочно забанить сам роутер
    [recidive]
    enabled   = true
    logpath   = /var/log/fail2ban.log
    banaction = nftables-allports
    bantime   = 1w
    findtime  = 1d
    maxretry  = 5

    ```
    *Замените 192.168.1.0/24 на вашу домашнюю или рабочую подсеть, чтобы Fail2ban никогда вас не забанил.*

1. *Fail2ban* нужен шаблон, по которому он будет распознавать неудачные попытки входа в веб-интерфейс - **/etc/fail2ban/filter.d/proxmox.conf**
    ```ini
    [Definition]
    failregex = pveproxy\[.*\]: authentication failure; .* peer=\[<HOST>\]
    ignoreregex =
    ```
1. Перезапустите службу *Fail2ban*, чтобы применить настройки, и добавьте её в автозагрузку:
    ```bash
    systemctl restart fail2ban
    systemctl enable fail2ban
    ```

### Памятка
- Не публикуйте веб-интерфейс Proxmox (`8006`) и SSH (`22`) напрямую в интернет и не настраивайте для них проброс портов на роутере.
- Для доступа извне используйте VPN в домашнюю сеть.
- Включайте брандмауэр Proxmox только после того, как подготовили правила, разрешающие доступ к веб-интерфейсу и SSH из вашей административной сети. Ошибка в правилах может лишить вас доступа к узлу.
- Отключите на роутере ненужный UPnP или проверьте, что он не создал проброс портов к серверу.
- Для аварийного выключения используйте
    ```bash
    pve-firewall stop
    ```

## Check list

- Проверьте, что обновления установлены, а узел и VM запускаются без ошибок.
- Настройте уведомления о задачах резервного копирования и ошибках, если в вашей конфигурации доступен почтовый сервер или другой канал уведомлений.
- При частых отключениях электричества подключите сервер к ИБП; при наличии поддержки настройте корректное завершение работы.
- После завершения настройки сохраните доступ к локальной консоли сервера и актуальные данные для входа в надёжном месте.
