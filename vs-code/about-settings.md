# About settings

## Level

| Уровень | Где изменить | Когда использовать |
| --- | --- | --- |
| По умолчанию | Встроенные значения VS Code; посмотреть их можно в Settings | Обычно не редактируют: это исходные значения, которые заменяются настройками других уровней |
| Пользовательский (User) | `Ctrl+,` → вкладка User; JSON — команда `Preferences: Open User Settings (JSON)`. Файл в Windows обычно находится в `%APPDATA%\Code\User\settings.json` | Личные предпочтения, действующие во всех проектах на этом компьютере: тема, шрифт |
| Удалённый (Remote) | Настройки сессии Remote SSH, WSL или Dev Container: `Ctrl+,` → вкладка Remote | Параметры среды, где открыт удалённый проект, например настройки расширений, работающих на удалённом компьютере |
| Рабочая область (Workspace) | `.vscode/settings.json` в корне проекта; для сохранённой многокорневой рабочей области — её файл `.code-workspace` | Согласованные настройки проекта, применимые ко всей рабочей области |
| Папка рабочей области (Workspace Folder) | Для многокорневой рабочей области — настройки конкретной корневой папки через Settings или её `.vscode/settings.json` | Когда в одной рабочей области несколько проектов и для одного из них нужны отдельные настройки |
| Для языка | Вложенный объект вида `"[markdown]": { ... }` в пользовательских, рабочих или папочных настройках | Когда параметр нужен только для определённого языка; это не отдельный файл или самостоятельный уровень |
| Политика организации | Задаётся администратором организации | Если настройка управляется политикой, обычные пользовательские и проектные значения не смогут её переопределить |

В общем случае настройки более конкретной области перекрывают менее конкретные: значения по умолчанию → User → Remote → Workspace → Workspace Folder. Для поддерживающих это параметров языковые переопределения применяются отдельно. Не все параметры доступны на каждом уровне — это можно проверить в описании параметра в Settings.

Рабочие и папочные настройки могут распространяться вместе с проектом. Не добавляйте туда пароли, токены, адреса внутренних прокси и другие персональные или секретные данные. Если настройка нужна только вам, оставьте её в User или Remote settings.

### Несколько пользовательских наборов: общие и индивидуальные

В VS Code можно создать несколько профилей, например «Работа» и «Личное»: у каждого могут быть свои настройки, расширения, сочетания клавиш и оформление. Однако профили не складываются одновременно — в конкретном окне активен один профиль.

Чтобы разделить общие и индивидуальные параметры:

1. **Общие для проектов на этом компьютере** храните в User settings активного профиля. Если у вас несколько профилей, в редакторе настроек используйте действие **Apply Setting to all Profiles** для конкретного параметра, который действительно должен быть одинаковым во всех профилях.
2. **Индивидуальные для контекста** храните в настройках соответствующего профиля. Создайте профиль через **File → Preferences → Profiles → Create Profile** или команду **Profiles: Create Profile**, затем переключайтесь командой **Profiles: Switch Profile**.
3. **Общие для команды настройки проекта** храните в `.vscode/settings.json` и добавляйте в Git. Они применяются поверх пользовательских настроек и могут переопределить их.
4. **Личные настройки только для одного проекта** не добавляйте в общий файл проекта. Можно сохранить их в отдельном локальном файле рабочей области `.code-workspace`, который не добавляется в Git, или использовать профиль, связанный с этой папкой/рабочей областью.

Итого: User settings — личная база активного профиля; Workspace settings — настройки конкретного проекта; профиль — отдельный комплект настроек для переключения между контекстами, а не ещё один уровень приоритета.
