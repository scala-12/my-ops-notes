# Ollama в VS Code: автодополнение, генерация и ревью кода

В этой инструкции VS Code работает на компьютере разработчика, а Ollama — на отдельном сервере в локальной сети `192.168.4.50`. Для всех задач используется Continue: отдельная быстрая модель отвечает за inline completion, а модель с поддержкой инструментов — за чат, генерацию и аудит.

## Выбор расширения

| Расширение | Где особенно полезно | Плюсы | Минусы и ограничения в локальной сети |
| --- | --- | --- | --- |
| [Continue](https://marketplace.visualstudio.com/items?itemName=Continue.continue) | Чат, генерация, контекст проекта, ревью и автодополнение | В одном расширении настраиваются отдельные модели для чата и autocomplete; можно добавить собственную команду `/audit-diff` и контекст Git Diff | Требует настройки `config.yaml`; скорость зависит от сервера, модели и сети |
| [Twinny](https://marketplace.visualstudio.com/items?itemName=rjmacarthy.twinny) | Inline completion и локальный чат | Ориентирован на FIM-автодополнение; подключается к удалённому Ollama, умеет прикладывать Git diff и имеет функции ревью | Меньше подходит, если нужна единая настраиваемая схема ролей и команд; Agent mode обозначен как экспериментальный. Локальная сеть не устраняет задержку инференса |
| [Llama Coder](https://marketplace.visualstudio.com/items?itemName=ex3ndr.llama-coder) | Простое автодополнение с Ollama | Минимальная настройка и поддержка удалённого endpoint | Функциональность ориентирована на autocomplete и ограниченный набор моделей; чат, работа с контекстом проекта и ревью не заменяют Continue |
| [Cline](https://marketplace.visualstudio.com/items?itemName=saoudrizwan.claude-dev) | Агентная генерация и многошаговые задачи | Работает с Ollama, исследует проект, предлагает правки и запрашивает подтверждение операций | Не предназначен для inline completion; агентные запросы обычно требуют больше контекста и времени, чем autocomplete |

**Рекомендация:** начните с Continue, если нужно одно расширение для всех трёх задач. Если приоритет — максимально отзывчивые подсказки, сравните Continue с Twinny на той же модели и сервере. Фактическая задержка зависит от сети, нагрузки, размера модели и настроек контекста.

## Подготовить [Ollama-сервер](../ai-services/ollama.md)
1. Разрешить доступ из сети или по ip-адресу.
1. Установить модели. К примеру, qwen2.5-coder:1.5b и qwen3:8b.
1. На компьютере с VS Code проверьте доступность сервера:

   **Windows PowerShell:**

   ```powershell
   Test-NetConnection 192.168.4.50 -Port 11434
   curl.exe http://192.168.4.50:11434/api/tags
   # Если работает, то ответ "TcpTestSucceeded: True"
   ```

   **Linux/macOS:**

   ```bash
   curl http://192.168.4.50:11434/api/tags # должна вернуть JSON со списком скачанных моделей
   ```

## Конфигурация Continue в VS Code

1. Откройте Extensions (`Ctrl+Shift+X`).
1. Найдите **Continue** от Continue и нажмите **Install**.
1. Откройте панель Continue и выполните команду **Continue: Open config.yaml** из палитры команд (`Ctrl+Shift+P`).

    Continue использует актуальную конфигурацию `config.yaml` со схемой `v1`; старый формат `config.json` устарел. На Windows файл обычно находится в `%USERPROFILE%\.continue\config.yaml`.

1. Настроить модели и команду аудита

    Замените содержимое Continue `config.yaml` этим примером. В данном случае IP уже указан для сервера из этой инструкции. Для другого сервера замените `192.168.4.50` на его адрес; общий формат endpoint — `http://192.168.X.X:11434`.

    ```yaml
    name: Home Ollama
    version: 1.0.0
    schema: v1

    models:
    - name: Qwen2.5 Coder 1.5B - Autocomplete
        provider: ollama
        model: qwen2.5-coder:1.5b
        apiBase: http://192.168.4.50:11434
        roles:
        - autocomplete
        autocompleteOptions:
        debounceDelay: 250
        maxPromptTokens: 1024
        onlyMyCode: true

    - name: Qwen3 8B - Chat and Review
        provider: ollama
        model: qwen3:8b
        apiBase: http://192.168.4.50:11434
        roles:
        - chat
        - edit
        - apply
        capabilities:
        - tool_use
        defaultCompletionOptions:
        contextLength: 8192
        temperature: 0.2

    prompts:
    - name: audit-diff
        description: Аудит текущего Git diff
        invokable: true
        prompt: |
        Проведи строгий аудит изменений в приложенном Git diff.
        Ищи только конкретные дефекты, внесённые этими изменениями:
        ошибки логики, проблемы безопасности, обработки ошибок,
        граничных случаев, производительности и совместимости.
        Не сообщай о стиле и гипотетических рисках.
        Для каждого замечания укажи приоритет (Critical, High, Medium или Low),
        файл и строку, сценарий воспроизведения, влияние и конкретное исправление.
        Если diff не приложен или не виден, попроси его добавить; не делай вид,
        что проверил изменения. Если дефектов нет, явно укажи это.
        Отвечай на русском языке и не изменяй файлы.
    ```

Сохраните файл и перезапустите Continue, если расширение не подхватило конфигурацию автоматически. В списке autocomplete выберите **Qwen2.5 Coder 1.5B - Autocomplete**, а для чата/Agent — **Qwen3 8B - Chat and Review**. Для роли `tool_use` выбранная модель и версия Ollama должны поддерживать вызов инструментов; если Agent mode не может вызывать инструменты, проверьте поддержку tool calling или используйте модель, которая её поддерживает. Обычный чат при этом остаётся доступен.

`contextLength: 8192` — стартовое значение, а не универсальный максимум. Увеличение контекста требует дополнительной памяти сервера. Проверить размещение модели и контекст можно на сервере командой `ollama ps`.

## Проверка работы

### Inline completion

1. Откройте файл с кодом и поставьте курсор после незавершённого выражения или начните новую функцию.
1. Начните печатать, например:
   ```python
   def normalize_email(value: str) -> str:
   ```

1. Дождитесь серого ghost text Continue и нажмите `Tab`, чтобы принять подсказку. Если её нет, убедитесь, что autocomplete включён в Continue, выбрана модель с ролью `autocomplete`, сервер доступен и точное имя модели присутствует в `ollama list`.

### Генерация кода по запросу

1. Откройте Continue Chat или Agent и выберите **Qwen3 8B - Chat and Review**.
1. Добавьте нужный файл или выделенный код в контекст.
1. Запросите конкретное изменение, например: «Добавь в этот модуль проверку входных данных и тесты для пустой строки».
1. В Agent mode проверьте предложенный diff и подтверждайте изменения только после просмотра.

### Аудит и ревью изменений

1. Убедитесь, что проверяемые изменения находятся в Git diff.
1. Откройте Continue Chat/Agent и добавьте контекст **Git Diff** через picker контекста (`@Git Diff`, если этот источник доступен в установленной версии). Если источника нет, скопируйте diff из Source Control или терминала и приложите его к сообщению.
1. Вызовите prompt-команду:
   ```text
   /audit-diff
   ```

1. Проверьте замечания по исходному коду и diff вручную. Результат модели — вспомогательный review, а не подтверждение отсутствия дефектов.

Если запросы зависают или возвращают ошибку, сначала проверьте `/api/tags` с компьютера разработчика, совпадение имён моделей в Continue и Ollama, а также логи Continue в **View → Output**.
